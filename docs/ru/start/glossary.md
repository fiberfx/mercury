Эти семь терминов встречаются на всём сайте. Для каждого объясняется его значение в Mercury и приводится ссылка на соответствующий урок.

## sid

Стабильный идентификатор единицы Hypergraph вместе с описанием структуры (shape), позволяющий снова найти хранилище (store) после правки, при серверном рендеринге или в другой среде выполнения. По замыслу компилятор должен назначать sid каждому хранилищу, событию (event) и эффекту (effect). Но сегодня его проход назначения sid обрабатывает только вызовы прежнего фасада: у единицы Hypergraph есть sid лишь тогда, когда вы задали его сами; без этого она получает идентификатор времени выполнения `api:<n>`, пока её не именует компилятор. Пока компилятор не выдаёт и описания структуры, ядро определяет структуру каждого хранилища по его начальному значению. Кадр состояния (frame), который записывает изолированная область состояния (scope), использует sid как ключи значений, поэтому кадр из одной сборки можно применить в другой. Если значение нужно находить повторно, sid можно задать вручную через параметр хранилища `sid`; сегодня для единицы Hypergraph это единственный способ его получить. При `mx dev` путь модуля в `mx.mod` приложения задаёт пакет для sid его модулей. Это ещё не обеспечивает сохранение состояния Hypergraph после правки модели: проход назначения sid пока не поддерживает его единицы.

Подробнее: [Hypergraph](/ru/hypergraph) и [Единицы Hypergraph](/ru/hypergraph/units).

## Изолированная область состояния (scope)

Изолированная таблица состояния в Hypergraph. `Scope` — небольшой дескриптор `{id, gen}`, где `gen` — текущее зафиксированное поколение графа. `fork` создаёт такую область; `allSettled` запускает в ней единицу Hypergraph и завершается, когда в области больше нет выполняющейся работы; `snapshot` и `apply` записывают и восстанавливают её кадры состояния, а `dispose` завершает её работу. У каждого теста и каждого серверного рендеринга своя область состояния, поэтому значения между ними не разделяются. Область переживает горячую замену: переходит к новому поколению и сохраняет каждое значение, у которого по-прежнему совпадают sid и структура.

Подробнее: [Области состояния](/ru/hypergraph/scopes). Если вы переходите с другой библиотеки управления состоянием: [/hypergraph/coming-from-effector](/ru/hypergraph/coming-from-effector).

## Остров (island)

Компонент Mercury Hyperscript, смонтированный на одном элементе страницы, которую уже сформировал сервер. Сервер сначала отдаёт страницу как HTML, а остров добавляет интерактивность только там, где она нужна. В LiveView его монтирует `MercuryHook`: элемент с `phx-hook="MercuryHook"` и `data-name="X"` отображает компонент `X` с его props. Каждый остров имеет собственный корень рендеринга, поэтому два острова на одной странице нумеруют свои идентификаторы независимо. Команда `mx build --lib` собирает бандл острова.

О корнях рендеринга рассказывают [Основы](/ru/ui/foundations); о принципе — [Философия](/ru/start/philosophy). Острова подробно рассматривает курс Live Mercury.

## Версия для агентов (companion)

Написанная вручную версия страницы для агентов в обычном тексте. Рядом с каждым уроком `<name>.md` лежит его версия `<name>.llms.md`, доступная по адресу страницы с добавленным `/llms.txt`. При загрузке сайта урок без такого файла отклоняется. Версии для агентов не генерируются.

Подробнее: [Для агентов](/ru/start/agents).

## Уровень готовности (tier)

Показывает, насколько можно полагаться на модуль или страницу. **Shipped — опубликовано** в реестре пакетов. **Preview — предварительная версия:** код собран и протестирован в репозитории Mercury, но не опубликован. **Planned — запланировано:** возможность описана в плане, но не реализована, поэтому примера для запуска нет. Пятнадцать публичных модулей `@fiberfx` версии 4.0.0 имеют статус Shipped: они доступны в npm с 2026-11-05. `mx`, `live_mercury` и внутренние модули имеют статус Preview.

Подробнее: [Стабильность](/ru/start/stability).

## mx.work

Файл, который объединяет совместно разрабатываемые модули в одну рабочую область, подобно `go.work` в Go. Участники перечисляются в блоке `use ( … )`. `mx` ищет файл сначала через `-workfile`, затем через `MXWORK` (значение `off` отключает рабочую область), затем берёт ближайший `mx.work` выше рабочего каталога. Собственный файл Mercury — `fiberfx/mx.work`; он перечисляет восемнадцать модулей.

Подробнее: [Рабочие области](/ru/mx/workspace).

## Участник рабочей области (member)

Каталог, который рабочая область или приложение собирает из исходников. В `mx.work` участник — каталог, у которого в `package.json` есть `name`. Участник без имени отклоняется: `error reading <file>: missing name`. При `mx dev` участниками приложения являются каталоги, подставляемые через `mx.mod`; каждый обслуживается по адресу `/@mx/<package name>/`.

Подробнее: [Рабочие области](/ru/mx/workspace) и [Ваше первое приложение](/ru/mx/first-app).
