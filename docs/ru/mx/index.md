mx — набор инструментов Mercury: один исполняемый файл на Rust, версия 0.1.0. Он читает `mx.mod` модуля и `mx.work` рабочей области, обслуживает приложение с горячей перезагрузкой, собирает его в бандл и тестирует. Для этого ему не нужны Node и npm.

## Что такое mx

- **Система модулей по образцу Go.** Модуль объявляет себя в `mx.mod` и фиксирует загруженные зависимости в `mx.sum`. Модули, разрабатываемые вместе, объединяются в одном `mx.work`. Команды `mx mod …` и `mx work …` управляют этими файлами так же, как `go mod` и `go work` — своими.
- **Сервер разработки.** `mx dev` обслуживает приложение на 127.0.0.1, встраивает карту импортов в страницу и компилирует каждый модуль по запросу.
- **Сборщик бандлов.** `mx build --bundle` собирает страницу приложения с помощью Rolldown, встроенного в сам mx. Поэтому для сборки не нужен `node` в PATH.
- **Средство запуска тестов и сопутствующие инструменты:** `mx test` выполняет тесты модуля в браузере без графического интерфейса, который mx запускает сам; `mx compile` запускает Hypercompiler для одного файла; `mx lsap` запускает языковой сервер Hyperscript, установленный рядом с mx.

Это отдельная рабочая область Rust в `fiberfx/mx`, а не приложение Mix.

## Команды

`mx` без команды выводит строку использования и завершается с кодом 2:

```sh
usage: mx exodus|pack|install|verify|importmap|resolve|scan|build|check|run|compile|work|dev|test|lsap …
```

Ещё одно семейство команд обрабатывается до этого разбора и отсутствует в строке: `mx mod`, у которого собственная строка использования — `usage: mx mod <init|tidy|verify|graph|why|download>`.

Команды, принимающие флаги, выводят строку использования при неизвестном флаге:

```sh
usage: mx dev [--root <dir>] [--port <n>] [--importmap]
usage: mx test [--root <dir>] [--timeout <seconds>] [--filter <words>]
usage: mx compile <file> [--options <json>] [--out <file>]
usage: mx build [--bundle] [--root <dir>] [--out <dir>]
usage: mx lsap [--mcp] | mx lsap --version
usage: mx work edit|use|init|sync|vendor …
```

`mx build --help` выводит описание всех трёх видов сборки: хоста, приложения (`--bundle`) и библиотеки (`--lib`). Там же указано, как mx выбирает вид, если он не задан: `mx.json` означает сборку хоста, а `index.html` рядом с `mx.mod` — бандл приложения. `--help` вызывает справку только в качестве первого аргумента. В первом уроке разобрано, как `mx build` принимает это решение.

## Как отвечает mx

У всех команд общий контракт:

| Код завершения | Значение |
|---|---|
| 0 | успех |
| 1 | отказ: входные данные неверны, причина указана в сообщении |
| 2 | ошибка использования: неверная командная строка |

Диагностика поступает в stderr, поэтому собственный вывод команды в stdout, например JSON от `mx dev --importmap`, можно передать по конвейеру. Одна команда добавляет код: `mx test` завершается с кодом 3, если проверку выполнить не удалось, потому что браузер не найден.

## Установка mx

В уроке [Установка mx](/ru/start/install-mx) описаны загрузка нативного архива для Linux x86_64 и стартового приложения, проверка SHA-256, `mx install` и `mx verify`. Для этого пути не нужны Rust, Node.js, npm CLI, BEAM и репозиторий. Урок [Первая страница](/ru/mx/first-app) создаёт оформленный счётчик Card + Button.

## Главы

1. **MX0 — первое приложение:** [приложение — это `index.html` рядом с `mx.mod`](/ru/mx/first-app); запустите его через `mx dev`, соберите через `mx build --bundle`.
2. **MX1 — модули и рабочая область:** [`mx.mod`, `mx.sum` и `mx mod`](/ru/mx/modules), затем [`mx.work` и `mx work`](/ru/mx/workspace).
3. **MX2 — цикл разработки и HMR:** [что обслуживает `mx dev` и как сохранённая правка попадает на страницу](/ru/mx/dev).
4. **MX3 — сборка и поставка:** [`mx build --bundle`, `--lib`, сборка хоста и `mx check`](/ru/mx/build).
5. **MX4 — Hypercompiler:** [`mx compile` и преобразования каждого модуля, который обслуживают mx dev и mx build](/ru/mx/compile).
6. **MX5 — инструменты:** [`mx test`, `mx lsap` и `mx run`](/ru/mx/tools).

Итоговое задание курса — собрать нативное приложение без `node` в PATH. Для такой проверки подходит сохранённый пример `sites/mercury`; действующий сайт документации работает как Phoenix-приложение `mercury_lms`.

## Что поставляется

[Метаданные выпуска](/downloads.json) указывают нативный архив и ревизию исходников. Публичная инструкция для первой страницы рассчитана на Linux x86_64; macOS и Windows требуют отдельных проверок. Все шесть глав, от MX0 до MX5, написаны.
