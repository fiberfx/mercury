# Mercury Brand Book

Make Mercury guidance readable, editable, and traceable to the actual design system. Preserve the supplied book and distinguish established identity, observed implementation, proposed guidance, and verification limits. A reader is a presentation of that source; personal settings and token experiments do not change the approved brand.

## Choose the useful increment

Identify the audience, source edition, requested change, formats, destination, and observable reader benefit. Reuse answers already present. Follow the lightweight flow **UNDERSTAND → ESTIMATE → EXPAND → SYNTHESIZE → EXECUTE → COMPLETE**: resolve meaningful unknowns, choose the smallest supported implementation, then deliver checked value. Estimate uncertainty and a finite investigation/checkpoint appropriate to the work; keep routine framing internal. Return from EXPAND to UNDERSTAND if the premise changes, or ESTIMATE if scope grows; a frame-changing execution surprise returns to UNDERSTAND. COMPLETE reports Delivered or Blocked, not acceptance. Do not turn trivial edits into a phase ceremony.

Read only the reference needed:

- [Source and format fidelity](references/source-and-formats.md) for authoring, source reconciliation, packaging, or exports.
- [Reader UX and research](references/reader-ux.md) for interactive reading, units, fonts, colors, SVG, and browser verification.
- [Mercury edition notes](references/mercury-edition.md) when using the documentation-interface book as a starting point; revalidate these dated values against the supplied edition.

## Preserve the real system

Inspect the provided book, asset provenance, theme definitions, and current host before choosing tooling. Keep authoritative editable content separate from reader state. Reuse supplied SVG masters and semantic color roles; preserve the distinction between shared Mercury UI tokens and application tokens. Do not fabricate logo geometry, token names, or library APIs.

For a Mercury application, use the available `mercury-design-builder` skill to choose genuine UI/Hyperscript components and a supported host workflow. If unavailable, inspect the installed package contracts and matching documentation directly. Preserve the existing framework, entry points, dependency pins, and working interactions. This skill supplies editorial and reader guidance, not an alternate component library or a dependency on one machine's checkout.

## Deliver evidence with the artifact

Check content fidelity separately from rendering and interaction. Exercise one valid case and a relevant violating case at each changed boundary; use the focused checks in the relevant reference. Verify the actual requested outputs rather than promising every format. Report usable entry points, observed checks, and material limitations; unrun checks remain unrun. Format conversion does not grant publication, deployment, or source-repository write authority.
