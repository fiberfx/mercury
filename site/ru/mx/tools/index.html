Инструменты: test, lsap и run

Три команды вокруг рабочего цикла: mx test выполняет тесты в настоящем браузере, mx lsap запускает языковой сервер, mx run кеширует скрипт или запускает хост.

Сборку и цикл разработки дополняют три команды. mx test выполняет тесты в настоящем браузере, mx lsap запускает языковой сервер, а mx run — скрипты и хосты.

mx test

usage: mx test [--root <dir>] [--timeout <seconds>] [--filter <words>]

mx test выполняет тесты модуля в браузере без графического интерфейса, который mx запускает сам, используя тот же граф, который обслуживает mx dev. Успех не предполагается: каждый результат должен вернуться в mx. Запуск без тестов, с потерянным отчётом или без завершения считается неуспешным.

  • Какие файлы. Все файлы *.test.* или *.spec.* с расширением js, mjs, jsx, ts, mts или tsx под корнем. В node_modules, dist, target и coverage поиск не выполняется. Если файлов нет: mx test: no tests under <root>, код 1.
  • Сначала импорты. Если импорты тестового файла не разрешаются, до запуска браузера фиксируется ошибка с его именем: FAIL <url> > (its imports): <why>. Остальные файлы продолжают выполняться.
  • Браузер. Его задаёт MX_BROWSER. Иначе mx ищет самый новый Chromium, затем headless shell Playwright в PLAYWRIGHT_BROWSERS_PATH, ~/Library/Caches/ms-playwright или ~/.cache/ms-playwright.
  • --timeout ограничивает весь запуск, по умолчанию 120 с: the run didn't end within <n> s. Отдельно определяется зависание страницы, которая молчит ещё 30 с после истечения тайм-аутов всех её тестов; оставшаяся часть этого файла не выполняется.
  • --filter <words> оставляет тесты, у которых <file> > <name> содержит заданный текст, а остальные считает исключёнными фильтром.
Код завершения Значение
0 все тесты прошли
1 тест упал, ни один не выполнялся или запуск нарушен
2 ошибка использования
3 проверку выполнить не удалось: браузер не найден

Код 3 никогда не означает успех. mx перечисляет проверенные пути, затем выводит Set MX_BROWSER to a Chromium binary..

Что импортирует тестовый файл

Тестовый файл импортирует из vitest, но карта импортов страницы направляет этот импорт в собственную среду выполнения mx, а не в Vitest. Она предоставляет:

  • describe, it и test, а также хуки beforeAll, afterAll, beforeEach и afterEach;
  • expect с проверками;
  • vi: vi.fn, vi.spyOn, vi.stubGlobal, подменённые таймеры (vi.useFakeTimers, vi.advanceTimersByTime, vi.runAllTimers и другие), а также vi.setSystemTime;
  • expectTypeOf и assertType, которые ничего не проверяют во время выполнения: типы относятся к работе компилятора;
  • собственный visit mx.

Как и в Vitest, тесту отводится 5 с, хуку — 10 с. vi.mock отсутствует: его вызов выбрасывает vi.mock is not in mx test: a module is mocked by import map, later (mercury.mx.13).

Управление страницей через visit

async function visit(url, { width = 0, height = 0, scale = 1, mobile = false, scheme = null, ready = null } = {})

visit открывает страницу HTTP-origin в браузере текущего запуска через протокол DevTools, эмулируя заданные размер области просмотра, масштаб, мобильный режим и scheme как prefers-color-scheme. Промис разрешается, когда CSS-селектор ready находит элемент, а без него — после загрузки страницы. Если width или height не заданы, сохраняются размеры браузера.

Возвращённый объект предоставляет два метода:

  • evaluate(fn, ...args) выполняет fn на этой странице и разрешает промис её JSON-значением либо отклоняет его выброшенной ошибкой;
  • close() закрывает страницу.

Незакрытая страница visit закрывается после завершения её тестового файла. Если DevTools браузера перестаёт работать, mx завершает файл с указанием его имени.

Как читать результат запуска

Одна строка на тест, затем итоговые числа:

ok    <file> > <name>
skip  <file> > <name>
FAIL  <file> > <name>: <message>
mx test: <passed> passed, <failed> failed, of <total>

По карте исходников компилятора стек ошибки привязывается к исходной строке. Запуск также проверяет собственную полноту:

  • если число тестов со страниц не совпадает с числом полученных отчётов, выводится the pages counted N tests and M reports arrived и запуск считается неуспешным;
  • при --filter выводится число исключённых тестов;
  • если фильтр исключил все тесты, выводится no tests ran: the filter matched none, код завершения — 1.

mx lsap

usage: mx lsap [--mcp] | mx lsap --version

mx lsap запускает языковой сервер Hyperscript, hyperscript-lsap, который должен быть установлен в том же каталоге, что и mx. Другой сервер mx не запускает и запасного варианта не использует. Он передаёт серверу собственный путь через HYPERSCRIPT_LSAP_MX, чтобы импорты разрешались этим экземпляром mx, затем завершается с кодом сервера. Во время сеанса stdout сервера несёт протокол, поэтому сам mx туда ничего не пишет.

Релиз, собранный release.sh, содержит сервер: hyperscript-lsap-<target> лежит рядом с mx-<target>. Его нужно установить в тот же каталог, что и mx, под именем hyperscript-lsap. Исключение — Windows. Сервер поддерживает только Unix, поэтому Windows-релиз содержит лишь mx, а mx lsap отказывает с The language server isn't built for Windows in this release.

  • --mcp передаётся серверу без изменений.
  • --version выводит обе версии. На этой машине mx lsap --version вывел:
mx 0.1.0
hyperscript-lsap 0.1.0

Если рядом с mx нет сервера, команда завершается с кодом 1 и выводит Error: mx lsap found no language server beside mx., проверенный путь и Put hyperscript-lsap in <dir>: a release of mx ships it there..

Сервер написан на Rust. Сейчас это перенесённый языковой сервер TypeScript, собранный по правилам Mercury; собственные сведения Mercury он пока не предоставляет.

mx run

У mx run две формы, выбор между которыми определяется каталогом.

Задача. Если в package.json текущего каталога есть скрипт с указанным именем, mx run <name> запускает его как кешируемую задачу. Ключ — sha256 от:

  • скрипта, его аргументов и положения модуля в рабочей области;
  • NODE_ENV и имён, перечисленных в MXRUN_ENV;
  • sha256 каждого входного файла и используемых инструментов.

При попадании в кеш mx проверяет каждый сохранённый объект, восстанавливает выходные файлы и воспроизводит журнал: mx run: <member> <task>: hit <key>, restored N files. При промахе указывается первое различие: mx run: <member> <task>: miss (<why>). Сохраняются только результаты с кодом 0, в MXCACHE, по умолчанию ~/.cache/mx/run.

Флаги ставятся перед именем скрипта:

Флаг Действие
--no-cache выполнить скрипт, не читая и не сохраняя запись кеша
--verify при попадании в кеш повторно выполнить задачу и сверить выходные файлы с сохранёнными
-r, --recursive выполнить задачу у каждого участника рабочей области
--filter <member> выполнить задачу у названных по каталогу или имени пакета участников и у всех участников, от которых они зависят
-j <n> число параллельных задач; по умолчанию число процессоров, но не более 4

-r и --filter требуют mx.work: mx run: -r and --filter need an mx.work at or above <dir>. Скрипт mx test никогда не кешируется, поскольку mx test читает всю рабочую область из исходников: mx run: <member> <task>: uncached: mx test reads the workspace from source.

Хост. Любое другое имя сохраняет форму для хоста: mx run <command> [args] собирает хост (MX3), затем передаёт управление команде, сохраняя её сигналы и код завершения. Пример из исходников mx — mx run mix phx.server.

Если имя не задано, mx run отвечает mx run: a command is required.
